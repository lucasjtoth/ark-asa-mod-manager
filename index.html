📖 Recommended Mod Load Order in Singleplayer

The mod load order in ActiveMods= determines which mod takes priority when initializing game assets. This manager automatically categorizes mods into 7 logical tiers. You can manually override any mod's tier at any time using the colored dropdown on its card.

1. Overhaul Mods (Top Priority) Position #1

Total Conversions and Core Overhauls that rewrite core world mechanics, dino tiers, and spawns. Must always load first at position #1.

2. Official Events Right Below Overhaul (or #1 Without Overhaul)

Official Studio Wildcard seasonal events (e.g., Fear Ascended, Winter Wonderland) that apply a global World Buff — adding event spawns, color regions, and holiday craftables to the base game or overhaul.

3. Stacking & Core Loot Mods Below Events

Dedicated tier for mods that alter item stack sizes, resource weight reductions, core item remaps, supply crate overhauls, and death inventory keepers.

4. Creatures, Spawns, Mutations & Taming Upper Middle

Mods adding new creature species or variants (Shiny!), modifying spawn containers, mutations, traits, bosses, and taming mechanics.

5. Structures, Storage & Logistics Middle of Load Order

Building sets, base automation, dedicated/visual storage, and creature capture balls (e.g., Dino Depot, Cybers Structures). Placed after creatures so they properly recognize modded dinos and traits.

6. Rebalance, Weapons, Saddles & QoL Lower Middle

Player movement tweaks, spyglasses, weapons, custom saddles, explorer note trackers, and general Quality of Life utilities.

7. Decor, Furniture, Landscaping & Music Bottom of Load Order

Aesthetic craftable structures, furniture, foliage/landscaping props, and music players. Since they do not alter core game mechanics, they belong at the very end of the Load Order.

❌ Custom Cosmetics & Standalone Maps Do Not Add to GUS.ini

Purely cosmetic skins (Custom Cosmetics) and standalone map mods are automatically hidden from the gameplay mod catalog because ASA loads them separately without adding them to ActiveMods=.

📂 1. Which Files Are Modified vs. Read-Only (Backups) Read & Write

• Read-Only Access: The library.json file and the entire 83374 mods directory (Manifest_UFSFiles_Win64.txt) are strictly read-only. This tool never writes to or modifies them.
• Modified Files (Backup Recommended!): This tool only writes to GameUserSettings.ini (the ActiveMods= line) and Game.ini (under [/Script/ShooterGame.ShooterGameMode]). Always back up these two .ini files (and ideally your Saved/SavedArksLocal folder) before making major changes.

🛑 2. Safe .ini File Practices (Close Game First & Read-Only Flag) Important

• Always close the game first: Never edit or save GameUserSettings.ini or Game.ini while ARK is running in the background (even in the main menu). The game overwrites config files from memory upon exit or map load.
• "Read-Only" Attribute on Game.ini: ARK: Survival Ascended sometimes wipes or truncates long custom entries in Game.ini on startup.
  ↳ Workflow: Before saving in this tool, right-click Game.ini in Windows Explorer ➔ Properties and uncheck "Read-only", save your changes here, and then re-check "Read-only" before launching the game. (If the file remains Read-only while saving, the browser cannot write to it.)

⚠️ 3. Limits of Heuristic Detection (Load Order, Manifests, Recipes & Loot) Heuristics

• Heuristic Estimation: Every mod author uses different folder structures and naming conventions. Automatic sorting into Tiers 1–7 and manifest asset extraction (83374) rely on smart heuristics.
• Verify Load Order: If a mod is auto-assigned to the wrong tier, always check the mod author's description on CurseForge and manually change its tier via the card dropdown.
• Internal Blueprints & Invalid Recipes: The folder 83374 scanner may list internal helper blueprints where hiding the engram, overriding crafting costs, or adding to supply crates has no effect in-game, or using an invalid resource class may make an item uncraftable.
• Troubleshooting: Test changes incrementally. If a specific recipe, engram, or loot override does not work as expected in-game, simply delete that rule in the left panel (✖) or restore your backup .ini file.

💡 4. Additional Practical Warnings Tips

• Removing Mods from an Active Save: If you remove a mod from ActiveMods= while having placed structures, stored items, or tamed creatures from that mod in your world, they will permanently vanish when loading the save.
• Testing Supply Crate & Dino Drop Changes: ConfigOverrideSupplyCrateItems changes only apply to newly spawned supply crates and creatures (not those already existing in the world prior to the edit — use cheat DestroyWildDinos in-game to refresh wild creatures).
• Browser Storage: Draft pools and GUS profiles are stored in your browser's localStorage. Clearing browser site data (e.g., via CCleaner) will erase saved browser profiles.
